# Auction and buyback history: bounded event helper

For **current branch/license-auction status**, use `python3 -B -I scripts/snapshot.py auctions`: it fetches fresh, pinned state from the v1.1 license auction. No discovery or history scan is needed for current price, supply or round context. Charter-specific allowance needs [supplemental getters](auctions.md#current-branch-auction-status-getters-first), not logs or an invented helper input. The installed skill holds identities/interfaces and historical cutover provenance, never a saved current-status fallback.

Use `scripts/history.py` only for requested bounded historical license/post-genesis charter purchases, quantity-weighted event-accounted consideration and observed roll capacity. The [auction event catalog](../assets/interfaces/auction-events.json) supplies fixed generation identities and authenticated events; [source provenance](../assets/sources/live-interface.json) distinguishes `sr-auction-event-interface` (legacy), `sr-v1-1-read-interface` (publisher-adapted retained events) and `sr-v1-1-deployment-evidence` (creation/cutover). [Auctions](auctions.md) describes the design, not a saved historical-settings table. Results are fetched on demand, written only to stdout and never saved by the helper.

Two separate treasury history modes use the [treasury event catalog](../assets/interfaces/treasury-events.json): `buybacks` reports Contraction Vault `BuybackExecuted(uint256,uint256)` burn accounting; `pol-buybacks` reports POL Buyback `BuybackExecuted(uint256,uint256,address)` raw output and destination, **not burns**. Their source records are `sr-extended-read-interface` and `sr-pol-buyback-event-interface` respectively. Neither mode accepts a day filter. Shared finite scanning, canonical-header checks, transport diagnostics and stateless behavior apply to all modes. Authorized external exports/caches or requested bounded monitoring do not change this helper contract.

Prefer this helper when it covers the question; it is not an exclusive route for public history. Other events, receipt reconciliation, ownership discovery or additional historical state may use [supplemental public reads](inspection.md#supplemental-public-reads) with bounded tools or locally authored read-only request code. Retain coverage, decoding and block-consistency evidence. The ceilings and stop/no-automatic-fallback behavior below describe this helper; independent permitted public sources can be researched separately without rewriting its output or evading any source's access controls.

For reliability-sensitive larger history, Robinhood's [official connection guidance](https://docs.robinhood.com/chain/connecting/) recommends Alchemy for production and archive nodes for historical reads/indexing; the public RPC is rate-limited and not recommended for production. This helper selects `SRSTACK_RPC_URL` > `ALCHEMY_API_KEY` > the official public default, retaining bounded budgets and stop-on-error behavior without automatic alternate-provider fallback. Supply an optional Alchemy key or custom HTTP/HTTPS endpoint through host-managed environment secrets; prefer HTTPS for credentials and keep keys out of outputs. See [provider configuration](execution.md#rpc-provider-guidance) for path/query and Basic authentication support. The recommendation does not restrict provider selection or establish a plan's historical coverage. No installed live state or endpoint-health snapshot establishes present availability.

## Question to window

Load this section and the input/output details needed below, not the full reconstruction guide by default. Reuse relevant observations already obtained; do not add price calls.

| Question | Minimal operational path |
|---|---|
| Purchases in current / previous round | If the round is not specified, read `snapshot.py auctions` once. Use its elapsed-round context and generation, not stale `currentDay()` storage. “Previous” means preceding elapsed round, not the last nonempty row; round zero has no predecessor in that generation. Resolve an evidenced finite block window, then run the selected auction with `--day ROUND --from-block FIRST --to-block LAST`. Keep the emitting generation in the answer. |
| Last round with purchases | Scan a finite recent window without `--day`; select the latest checked purchase by block/transaction/log order, not highest day across generations. Use `--detail full` only if summary observations cannot resolve the order. Say “last observed in this window” unless coverage establishes the stronger claim. |
| Auction performance over dates | Resolve dates/timezone to `[start, end)` (UTC if unspecified, disclosed). Find `FIRST`, the first canonical block at/after start, and `LAST`, the block before the first at/after end. Run `license` or `charter` over those inclusive bounds, without `--day`. Report quantities, consideration and quantity-weighted average **within the date window**, not complete-round totals. |

Resolve timestamps with a bounded block-timestamp index checked against RPC headers, or binary-search canonical `eth_getBlockByNumber` headers under one pinned head; verify neighboring boundary headers and retain hashes. The helper accepts blocks, not dates or “last round.” Never convert hours to guessed block counts. If the end extends beyond the observed head, cap there and label the result “through observation”; no blocks in the interval means no scan, not a reversed range.

For a round window, authenticate interval-specific anchor, duration and effective changes before deriving scheduled boundaries; today's period is not historical proof. When that evidence is absent, choose a finite search window and report **observed round purchases in that window**, with opening/completeness unavailable. A lazy stored round, skipped index or empty response does not establish a completed round with zero sales. Supplemental historical state/receipts remain available when the requested conclusion needs them.

Default output is one small table: `generation / round | quantity | event-accounted consideration | weighted unit price`, then UTC window and coverage gaps. Omit unrequested detail. Sum unrounded raw consideration and quantities before calculating a window-wide weighted price; never average round averages or mix ETH charter payments with STANDARD license charges. `status: ok` checks the requested window, not the entire round.

## Run a bounded scan

Run from the installed `srstack` root with the host's reviewed Python 3. These are templates: replace uppercase placeholders with evidenced decimal integers; do not execute guessed block numbers or round IDs.

```sh
python3 -B -I scripts/history.py license --day ROUND --from-block FIRST --to-block LAST
python3 -B -I scripts/history.py charter --from-block FIRST --to-block LAST
python3 -B -I scripts/history.py buybacks --from-block FIRST --to-block LAST
python3 -B -I scripts/history.py pol-buybacks --from-block FIRST --to-block LAST
```

For auctions, omit `--day` to group every observed round; `--day N` filters the **emitted round identifier**, not a UTC date. It neither narrows the topic query nor proves a round's lifetime is covered. A license `--day 0` can return **two distinct rows**, one per emitting address; round IDs restart across generations. Both buyback modes reject `--day` before network access.

Without explicit endpoints, `--anchor-block B` is an inclusive upper block; if omitted it is resolved once from a fresh head. `--lookback-blocks N` defaults to **1,000,000 blocks** ending there (clamped at genesis). This is a search span, not an assumption about block rate, elapsed hours or auction duration. Alternatively, supply both inclusive `--from-block A --to-block B`; that form cannot be combined with anchor/lookback flags and uses `B` as the integrity anchor. Historical anchors need not be fresh. The helper does not search for a day automatically or silently widen a range.

Both forms accept `--chunk-blocks N` (default/max **10,000**), `--max-chunks N` (default **100**, max **500**) and `--detail summary|full`. Compact summary is the default. Full detail adds bounded normalized decoded events, including exact emitting addresses, roles, entity IDs, positions and block/transaction hashes, under `evidence.decoded_events`; it does not fetch receipts or add RPC methods. There is no endpoint CLI flag; configure RPC through the environment above. There is no address, header, retry, denomination, output-file or persistence option.

Only charter purchase events include buyer addresses, exposed with `--detail full`. License purchase events have no buyer field; a charter's current owner cannot establish its historical buyer. Neither purchase event catalog is a record of unsuccessful bids.

Additional non-configurable ceilings are **5,000,000 requested blocks**, **4,096 individual JSON-RPC requests**, **64 MiB total response budget**, **1 MiB per HTTP response**, **10,000 returned logs**, **2,048 headers per window**, **1,000 emitted address/round pairs**, **180 seconds overall**, and the shared transport's **10-second request deadline**. A response containing **2,000 or more logs in one window** is conservatively saturated/incomplete. All limits are shared across both license emitters, not multiplied per address. One address-array log query covers both when applicable; a chunk crossing new deployment splits there and each resulting checked window consumes one `max-chunks` slot. If the span needs more chunks than allowed, the remaining range is missing, never silently widened or skipped. Bounds are ceilings, not provider guarantees.

Live HTTP requests are spaced at least **0.5 seconds** apart within the same overall deadline, rather than bursting the scan. This is a client request budget, not a claim about the provider's rate limit. A 429 still stops the scan with original-response diagnostics and missing coverage; no automatic retry, wait-and-resume loop or alternate endpoint. Controlled injected test transports do not sleep.

## Read the result

Auction JSON has `schema_version: 1`, `status: "ok"|"partial"`, `auction`, `rounds`, `coverage`, `errors` and `evidence`. Contraction Vault JSON instead has `kind: "buybacks"` and `buybacks`; POL JSON has `kind: "pol-buybacks"` and `pol_buybacks`. Neither includes auction/round/day-filter fields. Exit codes are **0** for a checked requested window, **4** for partial/unavailable history, and **2** for invalid input (`status: "error"`, `error.kind: "input"`). `status: "ok"` means the bounded window passed this helper's checks—not a complete round, independently reconciled movement or finality.

- `rounds[].day` is an exact decimal string. `address`, `contract_role` and `entity_id` identify its generation; `(chain_id, address, day)` is the round key, never `day` alone. `purchase_quantity` sums license counts, or one per charter purchase; `purchase_event_count` is separate.
- `consideration` has `basis: "purchase_event_accounting"`, `asset` (`STANDARD` or `ETH`), `decimals: 18`, exact `total_raw`, scaled decimal `total`, and `quantity_weighted_average_raw: {"numerator": "...", "denominator": "..."}` in the asset's raw units per license/charter. The fraction is reduced exactly. No purchases means the average is `null`, not zero.
- `observed_rolls` and `observed_activations` contain block number, block timestamp and transaction hash; rolls also contain their `reported_cap`. `first_observed_purchase` and `last_observed_purchase` use those same observation fields. Times are Unix seconds from checked headers, never synthetic opening times.
- `reported_round_cap` is available only from a consistent `DayRolled` naming that same day. An activation event or unrelated configuration event cannot supply it. `scheduled_opening` and `time_to_sellout` remain `null`, `complete_round` remains `false`, and `sellout` is `"not_established"`: this event-only helper does not establish effective opening/configuration or a complete round. `gaps` states these limits and any requested-window gaps.
- `coverage.requested` records the resolved inclusive range. `completed` records non-overlapping checked windows, **`emitter_addresses`**, `scan_status`, matched-event counts and a checked-header digest; `missing` is the untrusted/unscanned remainder with a reason. Each window commits atomically for all its emitters. `scan_status: "logs_checked"` means an explicit log query was checked. `"no_deployed_emitters"` means catalog-proven pre-deployment scope: no log request or nonexistent-contract code check was made, but window headers and anchor were still checked. These windows count toward budgets and can be invalidated by reorgs. A failure before resolving an implicit head leaves unavailable endpoints `null` while `coverage.selection` retains the input. `coverage.day_filter` is the emitted-ID filter or `null`. Empty windows never create zero-sale rounds; an activation/roll may produce a round with zero **observed** purchases, not a complete zero-sale claim.
- `errors` identifies the setup, failed window or final-anchor stage. An HTTP denial retains the original bounded `diagnostics` supplied by the shared snapshot transport. No further request is made by that helper invocation; this is evidence about that request, not proof of global endpoint availability or its underlying cause. Separate research may consult independent public sources under their own access rules, retaining distinct coverage and provenance.
- `evidence` identifies the fixed chain and credential-redacted selected endpoint, catalog hashes, anchor/header/code observations, retrieval UTC, limits and actual request/byte/log counters. `scan_emitters` lists each applicable address/role/entity and its inclusive scan range; `anchor_contracts` records each required address's code hash. `deployment_boundaries` identifies catalog-evidenced creation blocks, including when the requested interval is entirely earlier. License `license_generations` carries static creation/cutover provenance, **not current auction state**, and never substitutes for live reads. `response_bytes` counts successful response bytes, not the separately bounded HTTP-failure excerpt. Each request reserves one maximum-size response against the total budget. Per-window anchor/hash checks support retained committed windows after ordinary later failure. `final_anchor_check` reports matching, unavailable or changed.

The helper supports useful purchase accounting despite unavailable scheduled openings. It does **not** use current `lastSalePrice`, assume 24-hour rounds, claim sellout or independently reconcile consideration receipts. Those stronger conclusions need the additional evidence below.

### Buyback event accounting

`buybacks.basis` is `buyback_event_accounting`. `event_count` counts only checked `BuybackExecuted` logs, not transactions, transfers, all token burns or current cumulative counters. `eth_spent` sums only the event's `ethSpent`; `standard_burned` sums only `tokensBurned`. Each amount reports `asset`, `decimals: 18`, an exact decimal-integer `total_raw` and a scaled exact decimal `total`: ETH wei and raw 18-decimal STANDARD respectively. No float rounding, swap-price extrapolation, reserve-asset decimal assumption or protocol-wide burn substitution is used.

`first_observed_buyback` and `last_observed_buyback` contain the checked event block number, block timestamp and transaction hash, or `null` when no event is observed. Full detail exposes the individual normalized `ethSpent` and `tokensBurned` raw integer fields under `evidence.decoded_events`. These values are the event's reported accounting, **not independent proof of actual ERC20 movement, successful burn routing, net supply change or holder income**; no receipts, arbitrary token calls or traces are fetched.

The denomination follows the publisher's ETH18 Contraction Vault/pool display and canonical purchased-STANDARD buyback semantics, not the event field names alone. Before scanning, the helper checks `ContractionVault.standard()` against the fixed STANDARD identity and requires that fixed token's nonempty code and `decimals() == 18`, all at the scan anchor. These two zero-argument calls use only the reviewed callable catalog and fixed addresses. `evidence.anchor_standard_binding` records the successful check; failure leaves buyback amounts unavailable and stops before logs. An anchor binding does not prove identical implementation or token relationships throughout the earlier interval.

`observation_status` distinguishes `observed_events`, `no_matches_in_scanned_windows` and `unavailable`. Checked empty windows yield zero **observed** event counts and sums for those windows, never a claim that no buybacks ever happened. If no window can be committed (including after a reorg invalidates earlier windows), the count and amount totals are `null`, not zero. After a later ordinary failure, totals include only `coverage.completed`; the failed window contributes nothing, and `coverage.missing` remains explicit. `requested_range_complete` is false on any error or missing coverage; true still means only that this bounded scan passed its checks, not independently established completeness or finality.

For programmatic use, the buyback selection is `{"schema_version":1,"kind":"buybacks",...bounds}`; existing auction selections remain `{"schema_version":1,"auction":"license"|"charter",...bounds}`. These are distinct selections, not aliases; mixing `kind`, `auction` or a buyback `day` fails before network access. The supported CLI above supplies these fields automatically.

### POL Buyback raw event accounting

`pol-buybacks` is selected programmatically with `{"schema_version":1,"kind":"pol-buybacks",...bounds}`. Its `pol_buybacks.basis` is `pol_buyback_event_accounting`; it has **no `standard_burned` field** and is not an alias for `buybacks`. The reviewed explorer-decoded signature is `BuybackExecuted(uint256 ethIn,uint256 tokensOut,address indexed destination)`, with Ethereum Keccak topic `0xb226e46e9ea13f5bbac224e6b365c82beb22fbd42694f7721db493241b3337db`. The distinct Contraction Vault topic is `0x8e8412cac6b961b95ef832e2bac486977bbd29eb9725f9eddd97f3380c31f649`.

- `eth_in` sums reported `ethIn`, with `asset: "ETH"`, `decimals: 18`, exact `total_raw` and scaled `total`. It is reported input, not receipt-reconciled expenditure.
- `tokens_out.total_raw` sums the raw `tokensOut` fields. `asset`, `decimals` and scaled `total` remain **`null`**; the token denomination is unestablished by this interface. No invented `standard()` getter, arbitrary token probe or optional denomination override is provided. This arithmetic sum is not a claim about burned STANDARD or a portfolio value.
- `reported_destinations` groups the checked events by their emitted `destination`, with event counts and `tokens_out_raw`. Full detail retains the individual `ethIn`, `tokensOut` and indexed `destination` plus exact emitter. A reported destination is not proof of transfer, a permanent vault binding, incentive allocation, distribution or wallet income.
- `observation_status`, `event_count`, first/last observations and `requested_range_complete` use checked-window rules. No committed coverage means counts/raw totals and destinations are `null`; checked empty log windows mean observed zero and an empty destination list. If every completed window precedes the catalog-evidenced POL creation block **69178088**, `observation_status` is `"no_deployed_emitters"`: zero events/raw sums apply only to those checked pre-deployment windows, without any log query. Spanning windows split at creation and then query only the fixed POL address. An entirely pre-creation anchor requires no POL code. Reorgs invalidate both observations and totals; ordinary failures preserve only checked windows.

The source record authenticates an explorer-decoded event layout corroborated by a raw receipt and publisher deployment mapping, **not a complete POL Buyback ABI or source verification**. The helper fetches only logs/headers/code for this mode; the Contraction Vault STANDARD-binding preflight remains exclusive to `buybacks`. Each invocation reads its requested chain interval afresh; no example receipt balances or totals are installed.

## Retrieve a finite, auditable window

The supported helper performs these checks automatically against the selected RPC endpoint (the official public `https://rpc.mainnet.chain.robinhood.com/` by default):

1. After the caller's [trusted-runtime preflight](execution.md#trusted-runtime-preflight) authenticates the sibling script against the reviewed manifest, load literal `scripts/snapshot.py` through a no-follow descriptor read and compile those bytes. The loader checks path, regular-file identity, size and mid-read changes—not content provenance by itself. No user/network input supplies executable bytes, no ambient sibling import or downloaded code is used, and `-I` works without adding the package to `sys.path` or writing bytecode. This reuses transport/parsing/catalog routines, not current-state calls. A locally writable runtime or compromised interpreter remains outside that trust boundary.
2. Validate chain **4663**, event catalog structure and its reviewed contracts/events SHA-256 fingerprint (including generation boundaries/cutover provenance); cross-check entity IDs and fixed addresses against the callable/entity catalogs. Check the anchor header and code for every applicable emitter, never requiring the not-yet-created replacement at an old-only anchor. `buybacks` additionally checks fixed STANDARD binding/code/18-decimal denomination; `pol-buybacks` and auctions add no state calls. Code presence and interface identity are not independent bytecode/source equivalence or historical implementation continuity.
3. Issue explicit ascending, non-overlapping inclusive chunks with fixed catalog addresses and topic-zero OR filters. License windows include legacy throughout and new from creation; both addresses share one address-array query when applicable. Strict decoding applies each address's own authenticated event set, with atomic per-window accounting. Purchase, activation/roll and reviewed configuration/pause/ownership events are included; supporting Central Bank is not another log target. Day filtering is local after decoding. Each buyback mode queries only its respective fixed emitter/topic, never auctions, `Transfer` or protocol-wide burn events.
4. Enforce per-request, total-byte, request-count, log-count, header-count, round-count, span/chunk and time ceilings. Apart from the deterministic deployment boundary, there is no automatic splitting, retry, alternate source or failed-window skip. A provider error, malformed result or conservative saturation threshold stops at that window and reports the remaining range. A smaller window is a new explicitly chosen run, not hidden pagination.
5. Require a selected emitter, its own allowed topic, exact topic/data sizes, supported ABI types and zero-padded address words. Validate canonical RPC quantities, block range, nonzero hashes, boolean `removed`, log/transaction order and uniqueness across the whole combined response. Duplicate/conflicting positions are errors even across two emitting addresses, not additional purchases. Conflicting transaction/block identities are never merged.
6. Retrieve canonical-number headers for each event block and both window boundaries; attach only matching block timestamps. Re-read those headers plus the fixed anchor before committing a window. Check the anchor again at successful completion. A removed log or observed reorg excludes untrusted observations and invalidates all previously committed windows, which are listed under `evidence.invalidated_windows`; coverage then marks the requested range missing. No confirmation-depth or finality assumption is made.

An ordinary later failure preserves already checked windows and their event-accounted purchases or buybacks; the failed window is not partly summed. If the final anchor request alone is unavailable, the result is partial, previous per-window checks remain explicit and no stronger final check is claimed. A successful provider response can still silently omit logs; RPC consistency checks are not an independent completeness proof. The helper neither fabricates missing pages nor claims to detect undocumented truncation below its conservative threshold.

For **additional manual research**, retain bounded receipt/state evidence in the session or authorized external artifacts, not installed resources. Historical calls must remain pinned; archive errors cannot fall back to `latest`. A receipt can corroborate consideration only through successful execution and authenticated matching events, without double counting. There is no packaged receipt/accounting fallback.

## Reconstruct rounds without assuming 24 hours

Group by `(chainId, auction address/generation, emitted day)`. `day` is a contract round identifier, not a UTC date or evidence of a 24-hour round. For v1.1, distinguish the **12-hour auction round** from the **separate 24-hour charter cap window**; retained `licensesPerDay()` / `LicensesPerDaySet` names mean supply per round, not per 24-hour window. The [current publisher rule](auctions.md#published-v11-license-changes) anchors fixed cap windows at activation; deployed reset arithmetic and payment routing still require separate evidence. Historical timing needs interval-specific opening/ending rules, anchors, duration, pauses and configuration transitions. Do not apply today's settings or old `AUCTION_DAY` assumptions to every generation.

`AuctionStarted(day,startPrice)` is an activation marker. `DayRolled(day,startPrice,floorPrice,cap)` supplies a reported round's price parameters and capacity, but **neither event contains a timestamp, duration or closing reason**. A roll can be processed in a later transaction: its block timestamp is the observed roll time, not automatically the scheduled opening. The first purchase time is also not the opening. The reviewed ABIs contain no dedicated `AuctionEnded` or `SoldOut` event. Do not fabricate either or assume every round emits a roll when its clock expires.

Obtain the actual opening/expiry anchor from authenticated implementation semantics plus interval-specific state/events, or an original source that explicitly establishes it. Historical calls must stay pinned; an archive error cannot fall back to `latest`. Where only a roll observation is available, label it **observed roll transaction**, leave scheduled opening/expiry unavailable and still report supported purchases. Gaps in day IDs are unresolved rounds until activation, skipped/lazy rolls, no purchases, migration and coverage are distinguished; do not synthesize zero rows.

Use `DayRolled.cap` only for the round it names. `AuctionStarted` omits cap; first-round capacity needs separate historical evidence. `LicensesPerDaySet`/`ChartersPerDaySet`, decay/floor/reserve settings and controller events are change evidence, not proof of their effective round. If implementation or historical state is unavailable, do not guess whether a change affects the open round or the next one. A present `soldToday`, `remainingToday` or `lastSalePrice` is not a historical table.

## Quantities, actual consideration and sellout

- **Licenses:** sum `LicensesPurchased.count`, not transaction/event count. Retain each executed `unitPrice` in raw 18-decimal STANDARD; event-accounted consideration is `count × unitPrice`. Where available, corroborate it against the same successful receipt's publisher-bound `BranchesOpened(charterId,count,cost)`, matching charter, quantity and ordering without reusing one cost event. `cost` is the reported total STANDARD ledger charge; do not add it a second time. If receipts or the historical Bank relationship are unavailable, label the result purchase-event accounting rather than independently reconciled payment. A matching event is not proof of ERC20 movement, burn routing or holder income.
- **Charters:** each `CharterPurchased` represents one charter; `price` is its reported executed consideration in ETH wei. Do not substitute transaction `value`, a maximum-price input, refund-inclusive funding or a current quote. Further payment reconciliation requires authenticated receipt/event semantics and accessible evidence. Supplemental traces and nonbroadcast simulations are permitted under host approval, but simulated effects alone do not establish actual historical payment; no signing or submission.
- **Weighted average:** `sum(actual consideration) / sum(licenses)` for licenses, or total executed ETH consideration divided by purchased charters. Weight every multi-license purchase by quantity; never take the arithmetic mean of event unit prices. Use integer/rational arithmetic from unrounded raw values and round only for presentation. A zero denominator makes the average undefined, not zero. If only event-accounted consideration is established, name the average accordingly rather than claiming independently reconciled actual payments.
- **Sellout:** complete purchase coverage from the evidenced round opening, the historically applied cap and any effective changes must establish the first purchase that exhausts capacity. Reconcile without double counting; a partial log count equal to today's cap is not enough. The last observed purchase need not be the sellout. If the historical cap or earlier purchases are missing, sellout remains not established.
- **Time to sellout:** compute sellout block time minus **evidenced opening time** only when both endpoints and their semantics are established. Otherwise report available first/last purchase or observed-roll times with those labels, not “sold out in N hours.” Observations at block granularity are not sub-block wall-clock timings. No sellout means no opening-to-sellout duration; expiry and sellout are different outcomes.

## Report supported scope, not a fictional recap

A useful per-round result has round/generation, opening/end anchors (or explicit gaps), historically applied cap, purchase count, license/charter quantity, denomination, total executed consideration, quantity-weighted average, first/last purchase, sellout status/time and coverage status. Omit unrequested columns. Preserve raw inputs, source URLs, block/transaction hashes and calculations in the session, answer or authorized external exports/caches; never save a financial recap inside the installed package as a fallback.
