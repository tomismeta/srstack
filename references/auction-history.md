# Auction history: bounded event research

Use this path for “how did each auction go?”, licenses sold, actual purchase prices, weighted-average consideration, round capacity or time to sellout. It is **research**, not the current `snapshot.py` auction profile, a price-curve model or a new runner. The [event catalog](../assets/interfaces/auction-events.json) supplies reviewed event definitions and identities; [source provenance](../assets/sources/live-interface.json), `sr-auction-event-interface`, explains their scope. [Auctions](auctions.md) describes published design, not historical settings.

- Supporting Central Bank: `0x5977B25419f9c0dDcB2F89fE204955622f4F57ea`; literal ABI `_e`, `BranchesOpened` only for receipt-level consideration corroboration.

The official HTML links `app-BzDBLzVV.js`, whose literal import is `mountApp-DmwNsaDC.js`; the HTML also links that mount module directly. Its chain/deployment mapping and complete literal auction ABI arrays are the evidence, not the stale older app filename. Follow [bounded source recovery](contracts.md#recover-a-stale-frontend-source-link) if these assets move. Read text only; never execute downloaded JavaScript. Publisher binding authenticates an interface, not independent deployment/source equivalence. A different generation/address needs its own authenticated mapping and events.

## Retrieve a finite, auditable window

For a small demonstrator, cap the work at one auction address, an explicit range of at most 1,000 blocks, four log requests, 1,000 returned logs, 1 MiB per response and 30 seconds per request. For a larger requested history, choose explicit finite interval/chunk/request/byte limits before fetching; stop and report remaining ranges at those limits. Do not retry access denials or silently lift bounds. These are research budgets, not claims about provider limits.

1. Use an already permitted public source with the required capability. The packaged RPC is `https://rpc.mainnet.chain.robinhood.com/`; `eth_chainId` must return `0x1237`. Resolve the requested interval to explicit inclusive block numbers, retain their hashes/timestamps and retrieval UTC, and check contract-code presence at relevant anchors. A timestamp search is bounded and uses block headers, not an assumed block rate. Confirm any replacement/deployment boundary before combining addresses. Current-state support does not imply historical-state support.
2. Start with one selected auction address and a short explicit block range. For `eth_getLogs`, use `fromBlock`, `toBlock`, `address` and catalog `topic0` filters. A topic-zero OR array can select `AuctionStarted`, `DayRolled`, the purchase event and relevant configuration/pause events. A missing opening/cap anchor may require an explicitly bounded earlier window; do not silently expand into all-chain history.
3. Apply indexed filters in the right positions: `LicensesPurchased` has `[topic0, charterId, day]`; `CharterPurchased` has `[topic0, charterId, buyer, day]`; `AuctionStarted` and `DayRolled` have `[topic0, day]`. Encode indexed `uint256` as 32-byte hexadecimal words. Do not use the purchase-day topic position for a roll event. Shared event signatures still require the emitting address: license and charter prices have different denominations.
4. Bound requests, block span, response bytes, result count and retries before fetching. Prefer a small demonstrator window, then only the finite scope needed to answer. RPC `eth_getLogs` has no standard pagination cursor: split oversized windows without gaps. For an explorer/indexer, follow its documented page/cursor contract through the terminal page; retain every page and limit. A full result page, truncation, repeated cursor, provider cap, rate limit or failed range is incomplete coverage, not permission to discard that part. Do not invent indexer routes from a hostname or an application panel.
5. Keep emitter, block number/hash, transaction hash/index, log index, topics, raw data and provider. Order by block, transaction index and log index. Deduplicate overlapping windows by `(chainId, blockHash, transactionHash, logIndex)`; detect a conflicting block hash rather than merge forks. Exclude `removed` logs, recheck anchor and used block hashes, and report the confirmation/reorg policy without assuming finality.
6. Decode strictly from the catalog: exact topic/data word counts, types and indexed positions. Get timestamps from matching block headers; a provider's zero or absent log timestamp is not a real time. Retrieve successful transaction receipts when matching purchase/consideration evidence. Keep unrelated same-transaction events separate. A failed decode, failed receipt, missing range or unauthenticated emitter stops the affected total.

An empty successful query means only no matches within its demonstrated filters and covered range. It does **not** establish a complete zero-sale round, nonexistent deployment or zero financial value. Preserve a coverage ledger of requested/completed/missing windows and pages in the session, not in installed package resources.

## Reconstruct rounds without assuming 24 hours

Group by `(chainId, auction address/generation, emitted day)`. Here `day` is a contract round identifier, not a UTC date and not proof of a 24-hour interval. Use the round's evidenced opening and ending rules, activation/anchor, duration, pauses and configuration transitions; do not apply today's `AUCTION_DAY`, cap, floor, half-life or owner policy to earlier rounds.

`AuctionStarted(day,startPrice)` is an activation marker. `DayRolled(day,startPrice,floorPrice,cap)` supplies a reported round's price parameters and capacity, but **neither event contains a timestamp, duration or closing reason**. A roll can be processed in a later transaction: its block timestamp is the observed roll time, not automatically the scheduled opening. The first purchase time is also not the opening. The reviewed ABIs contain no dedicated `AuctionEnded` or `SoldOut` event. Do not fabricate either or assume every round emits a roll when its clock expires.

Obtain the actual opening/expiry anchor from authenticated implementation semantics plus interval-specific state/events, or an original source that explicitly establishes it. Historical calls must stay pinned; an archive error cannot fall back to `latest`. Where only a roll observation is available, label it **observed roll transaction**, leave scheduled opening/expiry unavailable and still report supported purchases. Gaps in day IDs are unresolved rounds until activation, skipped/lazy rolls, no purchases, migration and coverage are distinguished; do not synthesize zero rows.

Use `DayRolled.cap` only for the round it names. `AuctionStarted` omits cap; first-round capacity needs separate historical evidence. `LicensesPerDaySet`/`ChartersPerDaySet`, decay/floor/reserve settings and controller events are change evidence, not proof of their effective round. If implementation or historical state is unavailable, do not guess whether a change affects the open round or the next one. A present `soldToday`, `remainingToday` or `lastSalePrice` is not a historical table.

## Quantities, actual consideration and sellout

- **Licenses:** sum `LicensesPurchased.count`, not transaction/event count. Retain each executed `unitPrice` in raw 18-decimal STANDARD; event-accounted consideration is `count × unitPrice`. Where available, corroborate it against the same successful receipt's publisher-bound `BranchesOpened(charterId,count,cost)`, matching charter, quantity and ordering without reusing one cost event. `cost` is the reported total STANDARD ledger charge; do not add it a second time. If receipts or the historical Bank relationship are unavailable, label the result purchase-event accounting rather than independently reconciled payment. A matching event is not proof of ERC20 movement, burn routing or holder income.
- **Charters:** each `CharterPurchased` represents one charter; `price` is its reported executed consideration in ETH wei. Do not substitute transaction `value`, a maximum-price input, refund-inclusive funding or a current quote. Further payment reconciliation requires authenticated receipt/event semantics and an available public endpoint; no state-changing simulation or tracing workaround.
- **Weighted average:** `sum(actual consideration) / sum(licenses)` for licenses, or total executed ETH consideration divided by purchased charters. Weight every multi-license purchase by quantity; never take the arithmetic mean of event unit prices. Use integer/rational arithmetic from unrounded raw values and round only for presentation. A zero denominator makes the average undefined, not zero. If only event-accounted consideration is established, name the average accordingly rather than claiming independently reconciled actual payments.
- **Sellout:** complete purchase coverage from the evidenced round opening, the historically applied cap and any effective changes must establish the first purchase that exhausts capacity. Reconcile without double counting; a partial log count equal to today's cap is not enough. The last observed purchase need not be the sellout. If the historical cap or earlier purchases are missing, sellout remains not established.
- **Time to sellout:** compute sellout block time minus **evidenced opening time** only when both endpoints and their semantics are established. Otherwise report available first/last purchase or observed-roll times with those labels, not “sold out in N hours.” Observations at block granularity are not sub-block wall-clock timings. No sellout means no opening-to-sellout duration; expiry and sellout are different outcomes.

## Report supported scope, not a fictional recap

A useful per-round result has round/generation, opening/end anchors (or explicit gaps), historically applied cap, purchase count, license/charter quantity, denomination, total executed consideration, quantity-weighted average, first/last purchase, sellout status/time and coverage status. Omit unrequested columns. Preserve raw inputs, source URLs, block/transaction hashes and calculations in the session or answer; never save a financial recap as a package fallback.

Public logs and successful receipts can support purchase accounting even when historical state cannot be read. Archive access, opening/expiry semantics, payment reconciliation and source/bytecode correspondence each need their own evidence for the requested interval. If an endpoint or definition is unavailable, name exactly which conclusion it prevents and retain supported partial facts. Do not infer an unavailable historical API, fake an opening time or use the current helper as a substitute. Fetch results on demand; store no historical observations or validation examples in the skill.
